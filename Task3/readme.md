### Обновления:
- Технологии, находящиеся в статусе **Hold**, запланированы для полного вывода из использования.
- **Trial** обозначает экспериментальное использование для оценки внедрения.
- **Adopt** указывает на рекомендованные технологии для текущих разработок.
- **Asset** — активно использующиеся ключевые технологии.

# Роадмап изменений

## Этап 1: Анализ и планирование (0–2 месяца)

**Ключевые результаты:**
- Проведён аудит текущих систем и инструментов.
- Составлен детализированный план перехода к новой архитектуре.
- Определены границы доменов и их зон ответственности.

**Участники:** Архитекторы данных, DevOps-команды, аналитики.  
**Ресурсы:**
- Инструменты анализа (например, ERwin, dbt, Redgate).
- Совещания и ресурс на написание документации.

## Этап 2: Создание интеграционного слоя (3–5 месяцев)

**Ключевые результаты:**
- Развёрнута архитектура на базе Apache Kafka для потоковой передачи данных.
- Настроены изолированные API для связи между доменами.
- Основные данные перенесены в Lakehouse (объединение DWH и Data Lake).

**Участники:** Backend-разработчики, команды DevOps.  
**Ресурсы:**
- Серверная инфраструктура для Kafka и его компонентов.
- Облачное объектное хранилище (например, S3 или Yandex Object Storage).
- Планирование отказоустойчивости.

## Этап 3: Разработка витрины данных (6–8 месяцев)

**Ключевые результаты:**
- Разработан удобный портал самообслуживания для всех отделов.
- Интегрированы BI-инструменты с новой архитектурой хранилища.
- Настроены политики доступа и разграничены роли для безопасности.

**Участники:** Фронтенд-разработчики, BI-аналитики, DataOps.  
**Ресурсы:**
- Веб-фреймворки (например, React.js или Angular).
- Лицензии на BI-системы, такие как Power BI, Dremio или Tableau.

## Этап 4: Обновление и оптимизация процессов (9–12 месяцев)

**Ключевые результаты:**
- Миграция SQL Server 2008 завершена, переведены данные на PostgreSQL, Apache Iceberg или Delta Lake.
- ETL/ELT процессы оптимизированы для снижения времени выполнения задач.
- Внедрены системы мониторинга и алертинга для поддержки новой инфраструктуры.

**Участники:** DataOps, аналитические команды, DevOps.  
**Ресурсы:**
- Инструменты мониторинга, такие как Prometheus и Grafana.
- Настройка автоматических уведомлений о сбоях.

# Обоснование изменений

## Переход на современные хранилища данных
- Повышается производительность выполнения запросов за счёт новых технологий.
- Обеспечивается масштабируемость для работы с большими объёмами данных.

## Внедрение интеграционного слоя с использованием Kafka
- Облегчает взаимодействие между доменами через потоковую передачу данных.
- Гарантирует поддержку аналитики в режиме реального времени.

## Создание витрины данных
- Обеспечивает самообслуживание для всех подразделений без зависимости от IT-отдела.
- Упрощает процесс анализа данных для бизнес-пользователей.

## Оптимизация ETL/ELT процессов
- Снижаются затраты на обработку данных за счёт более быстрого выполнения задач.
- Повышается стабильность и надёжность систем за счёт улучшенной архитектуры.

## Внедрение современных BI-инструментов
- Расширяются возможности для визуализации данных и интерактивной аналитики.
- Повышается удобство бизнес-аналитиков и принятие данных пользователями.

**Итог:**  
Эти изменения позволят компании перейти к гибкой, современной архитектуре, которая лучше отвечает требованиям бизнеса и поддерживает рост компании в долгосрочной перспективе.
